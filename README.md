# DevPulse Load Testing Suite (Locust)

Comprehensive Locust load testing suite for **DevPulse** ([odineye.cse23.org](https://odineye.cse23.org)).

This test suite was generated by extracting all frontend routes, backend microservice APIs, and user journeys directly from `SEM5_DevPulse_Frontend` and the backend service contracts.

## 👥 Simulated User Personas & Weight Distribution

Locust models real-world traffic by mixing five distinct user personas:

| User Class | Weight | Persona Description |
|---|---|---|
| **`StandardDeveloper`** | **45%** | Active software engineers monitoring PR review velocity, checking DORA summaries, inspecting PR risks, and viewing team workload. |
| **`WebsiteVisitor`** | **20%** | Web users loading Next.js frontends, browsing the landing page, switching workspace tabs, and viewing dashboard charts. |
| **`EngineeringManager`** | **15%** | Team leaders managing project members, configuring alert policies, and triggering historical DORA recalculations. |
| **`IntegrationServiceUser`** | **10%** | Webhook and integration polling: checks GitHub repo sync status, Jira issues, Slack alerts, and notification channels. |
| **`AnonymousApiUser`** | **10%** | Public visitors, OAuth flow entry points, authentication checks, and demo alert webhooks. |

## 🚀 Getting Started

### 1. Environment Setup

The virtual environment `.venv` is pre-configured with Python 3.13 and Locust:

```bash
# Activate the virtual environment
source .venv/bin/activate

# Install dependencies if needed
pip install -r requirements.txt
```

### 2. Running via Locust Web UI (Interactive Mode)

To start the interactive web interface:

```bash
locust
```

Open [http://localhost:8089](http://localhost:8089) in your browser:
- **Host**: `https://odineye.cse23.org`
- **Number of users**: `10`
- **Spawn rate**: `2`
- Click **Start swarming** to watch real-time charts for RPS, Response Times, and Error Rates.

## 🏃 Pre-Configured Test Scripts

All scripts run headlessly against `https://odineye.cse23.org` and generate self-contained HTML reports and CSV summaries in `reports/`:

### 1. Smoke Test (Fast Endpoint Verification)
```bash
./run_smoke_test.sh
```
Runs 1 user for 30 seconds to verify all endpoints respond properly.

### 2. Standard Load Test (Realistic Daily Traffic)
```bash
./run_load_test.sh
```
Runs 10 concurrent users at 2 users/sec for 2 minutes.

### 3. Stress Test (Finding System Capacity)
```bash
./run_stress_test.sh
```
Ramps up to 50 concurrent users at 5 users/sec for 3 minutes to test gateway throughput and database connection pooling.

### 4. Spike Test (Burst Resilience)
```bash
./run_spike_test.sh
```
Generates a sudden burst of 100 users at 50 users/sec for 1 minute to test Redis rate limiting and recovery.

## 🎯 Filtering by Tags

Run only specific subsystems using Locust tags:

```bash
# Test only DORA and PR metrics
locust --headless -u 5 -r 1 --run-time 1m --tags dora,metrics

# Test only authentication and public endpoints
locust --headless -u 5 -r 1 --run-time 1m --tags auth

# Test only frontend Next.js pages
locust --headless -u 5 -r 1 --run-time 1m --tags frontend

# Test only administrative endpoints
locust --headless -u 5 -r 1 --run-time 1m --tags admin

# Test only integrations (GitHub, Jira, Slack)
locust --headless -u 5 -r 1 --run-time 1m --tags integrations
```

## ⚙️ Configuration & Custom Credentials

Override default behavior using environment variables:

| Variable | Default Value | Purpose |
|---|---|---|
| `TARGET_HOST` | `https://odineye.cse23.org` | Target domain under test |
| `DEVPULSE_USER_EMAIL` | `dev@demo.devpulse` | Seeded developer account |
| `DEVPULSE_USER_PASSWORD` | `Password123!` | Seeded developer password |
| `DEVPULSE_ADMIN_EMAIL` | `admin@demo.devpulse` | Seeded admin account |
| `DEVPULSE_ADMIN_PASSWORD` | `Password123!` | Seeded admin password |
| `AUTO_REGISTER_USERS` | `true` | Automatically register dynamic users if login fails |
| `DEFAULT_PROJECT_ID` | `1` | Fallback project ID for parameterized metrics |
| `DEFAULT_COMPANY_ID` | `1` | Fallback company ID for workspace endpoints |

Example:
```bash
TARGET_HOST=https://odineye.cse23.org USERS=20 SPAWN_RATE=4 ./run_load_test.sh
```

## 🛡️ Rate Limiting Note

The Spring Cloud API Gateway enforces Redis-backed rate limiting:
- **Replenish Rate**: 10 requests / second
- **Burst Capacity**: 20 requests

When load testing at high concurrency (>20 concurrent users with minimal think-time), HTTP `429 Too Many Requests` responses are expected and prove the rate limiting filter is actively protecting downstream microservices. The test suite automatically detects HTTP 429s and records them with backoff sleep.
